Começando (fluxo com o agente)

Você não cria nada à mão — descreve, o agente constrói:

  1. Na sessão do agente, dentro da pasta do projeto, peça as telas: "quero as telas de login e cadastro do meu sistema, que abre num dashboard com lista de produtos" (ou digite /design).
  2. Na primeira vez o agente pergunta a marca (cor primária, estilo de fonte, tom) e cria o design/design-system.css + design-system.md. Todos os canvases seguintes reutilizam.
  3. O agente cria um canvas por fluxo (ex.: login/, dashboard/), valida tudo e devolve o link: http://localhost:8765/viewer.html?canvas=login.
  4. Abra o link, teste o sistema funcionando e comente o que quiser mudar (próxima seção). O agente ajusta e o visualizador recarrega sozinho.
Dica: comece por um fluxo pequeno e concreto. O ciclo inteiro (gerar → testar → comentar → ajustar) fica visível em minutos.

Comentar e iterar (o ciclo de revisão)

Comentário na tela inteira

  1. Selecione a tela (um clique) e clique 💬 Comentar esta tela.
  2. Escreva o pedido. O visualizador copia uma mensagem formatada — cole no chat do agente:
[Design: design/login › Login (01-login.html)] aumentar o espaçamento do formulário

Comentário em um elemento específico 🎯

  1. Clique 🎯 Elemento (o cursor vira mira; Esc sai).
  2. Passe o mouse: cada elemento ganha destaque com o seletor e um trecho do texto.
  3. Clique no elemento e escreva o ajuste. Ele vira um alfinete numerado na tela.
  4. Marque quantos quiser e mande tudo de uma vez com ⧉ Comentários (n):
[Design: design/login › Login (01-login.html) › body > main > form > button "Entrar"] deixar este botão em largura total

O agente localiza pelo seletor (depois pelo trecho) e edita só aquele ponto. Alfinetes têm × para remover e não aparecem no PNG exportado.

Ciclo completo: comente → cole no chat → agente edita → o visualizador atualiza sozinho. Sem sair do navegador.

Modo fluxo (testar o sistema de verdade)

Duplo clique em uma tela abre o modo fluxo: a tela em tamanho real, interativa — você loga, navega, cadastra. A barra flutua no topo e sai da frente sozinha depois de alguns segundos sem mouse; qualquer movimento sobre a tela traz ela de volta. Na barra:

  • ◀ ▶ — volta e avança pelo histórico de navegação do fluxo.
  • ⟲ — reinicia o fluxo do começo (por tela).
  • 🎯 Elemento — liga o modo de comentar elemento dentro do modo fluxo, com a tela em tamanho cheio (o melhor lugar para isso).
  • 🌙 — alterna claro/escuro sem sair do fluxo.
  • ← Voltar — fecha o modo fluxo.

Um canvas pode navegar para outro (login → dashboard): o sistema inteiro é navegável, e o estado (quem logou, o que foi criado) atravessa os canvases. O botão ⟲ Reset fluxo da barra zera tudo.

Cenários de dados

O data.json de cada canvas pode ter cenários nomeados que sobrepõem os dados base — é como você valida estados sem tocar em código:

{
  "items": [ …dados padrão… ],
  "scenarios": {
    "vazio":   { "items": [] },
    "critico": { "items": [ { "qty": 0, … } ] }
  }
}

Selecione no visualizador e confira se cada cenário compõe bem (lista vazia, tudo abaixo do mínimo, falha de API). Trocar de cenário limpa o estado do fluxo — cada rodada começa limpa.

Como as telas ficam interativas

As telas incluem um runtime minúsculo e offline, o mock.js, e dados fictícios em data.json:

APIO que faz
await Mock.data('items')Lê os dados do data.json do canvas (com o cenário escolhido aplicado).
Mock.go('03-detalhe.html')Navega para outra tela do fluxo — inclusive de outro canvas: Mock.go('../dashboard/01-overview.html').
Mock.state.set('user', …) / .get('user')Estado do fluxo compartilhado no projeto inteiro (login de um canvas, leitura em outro).
Mock.toast('Salvo!')Feedback visual de ação simulada.
Mock.scenario()Nome do cenário ativo ('' para o padrão).

Regras que o agente respeita: nada de CDN ou URL remota (ícones SVG inline, fontes do sistema), tokens do design system para toda cor/espaçamento, os dois temas sempre funcionando, e a tela continua compondo mesmo se o JavaScript falhar.

canvas.json define a ordem e o tamanho: device é mobile (390×844), tablet (834×1112) ou desktop (1440×900), com width/height opcionais.

Design tokens e utilitários

O tokens.json é a fonte única de todos os tokens do design system (claro e escuro). A partir dele o gerador escreve dois arquivos gerados, que nunca se edita à mão: design-system.css (as variáveis var(--…)) e utilities.css (o vocabulário fechado de utilitários). Depois de qualquer mudança em tokens.json, regenere os dois:

node design/scripts/gen-tokens.mjs

A matriz de utilitários tem 140 entradas exatas (137 classes + 3 helpers [data-state=…]), cobrindo estas famílias:

FamíliaExemplos
Cores (fundo, texto, borda)bg-accent, text-muted, border-border
Espaçamentop-2, m-0, gap-3 e direcionais (px-, mt-, gap-x-…)
Tamanhow-full, h-screen, min-h-0…
Raiorounded-sm, rounded-md, rounded-lg
Tipografiafont-body, text-heading, leading-body…
Sombrashadow-card
Estadoshooks [data-state="hover"], [data-state="active"], [data-state="disabled"]
Classes banidas: paleta do Tailwind (bg-zinc-900) e valores arbitrários (text-[13px]). O vocabulário é fechado e toda cor vem dos tokens.

Componentes

As telas reutilizam instâncias de componentes vindas de design/components/ (o registro components.json mais um partial por componente). Uma instância nunca é markup solto de componente: é o partial embrulhado por um par de marcadores, com três argumentos obrigatórios (os únicos aceitos):

<!-- component:button size=md tone=primary state=default -->…<!-- /component:button -->

Os valores precisam estar nos enums do registro: size vale sm|md|lg, tone vale primary|ghost e state vale default|hover|active|disabled. Os espaços preenchíveis (slots) são pares de marcadores dentro da região, e o conteúdo entre eles é preservado byte a byte:

<!-- slot:label -->Entrar<!-- /slot:label -->

Precedência: marker-args-win

Os argumentos do marcador são a fonte de verdade da variante. A cada sincronização a região é rematerializada a partir do partial: data-size, data-tone, data-state e as classes de variante da raiz são re-emitidos a partir do marcador. O conteúdo dos slots e atributos data-* extras que você colocar na raiz sobrevivem intactos.

Sincronizar: sync e --check

Depois de editar um partial em design/components/ (ou os argumentos de um marcador), rode antes de apresentar qualquer tela:

node design/scripts/sync-components.mjs

Com --check o comando vira dry-run: mostra um diff arquivo:linha de cada região divergente, termina com código 1 se houver divergência e 0 se estiver tudo limpo, e nunca grava nada. O validador também aplica as regras de componente em qualquer .html não isento (independente do canvas.json) com os códigos component-unknown, component-variant, component-marker, component-divergence e slot-marker.

Exemplo: mudar a variante do Button

Instrução recebida: "mudar a variante do Button". O caminho documentado é editar o marcador e rodar o sync, sem reescrever markup à mão:

  1. Na tela, localize o marcador do botão e troque o argumento no próprio marcador (ex.: size=md vira size=lg): <!-- component:button size=lg tone=primary state=default -->…
  2. Rode node design/scripts/sync-components.mjs: a instância ganha data-size="lg" e as classes de variante de lg (o marcador vence).
  3. Valide antes de apresentar: node design/validate.mjs design/<canvas>.
Fonte única: no pacote, example/components/ é cópia byte-idêntica de assets/components/. Os partials se editam só na fonte única; a cópia do exemplo é referência, nunca alvo de edição.

Solução de problemas

  • "O canvas X ainda não existe aqui" — o canvas é criado pelo agente junto com as telas: peça as telas na sessão do projeto. Confira também se o servidor está rodando na pasta design/ do projeto e se o nome na URL (?canvas=…) está certo.
  • Porta 8765 ocupada — suba em outra: node design/serve.mjs 8766 e ajuste o link.
  • A barra não mostra 🎯 / ⟲ / ⏺ — o viewer.html do projeto está desatualizado; copie a versão atual da skill (pedir ao agente: "atualize os arquivos do design/ com a versão da skill").
  • Banner vermelho de problemas — clique para expandir: cada linha diz o código e o arquivo. Corrija (ou mande o agente corrigir) e recarregue.
  • Preferências esquisitas — cenário/tema/dispositivo ficam por canvas no navegador; limpar os dados do site reseta.
